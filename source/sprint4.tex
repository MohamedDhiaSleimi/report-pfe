\section*{Introduction}
\addcontentsline{toc}{section}{Introduction}

This sprint delivers the administration layer, multi-language support, and
in-app onboarding tutorials that complete the \domainterm{MES} solution.
Administrators receive a persistent navigation shell giving access to a
a paginated activity log, and a user role management interface. Cross-cutting
quality-of-life features include full internationalisation with English, French,
and Arabic support, automatic right-to-left layout for Arabic, and guided 
coach-mark tutorials shown once per screen on first use. This sprint also 
delivers machine performance dashboard for the \userrole{Supervisor}. No new
\techname{Business Central} tables are introduced in this sprint; all data is
derived by querying and aggregating the tables created in Sprints~1 through~3.

\section{Implementation}

\subsection{Backend Implementation}

No new \techname{Business Central} tables are created in this sprint. All
backend work consists of new query and aggregation procedures added to the
existing \techname{MES Web Service} codeunit (50126), reading from the tables
defined in Sprints~1 through~3.

\subsubsection{Dashboard Aggregation}

\texttt{fetchMachineDashboard()} accepts a \texttt{hoursBack} integer and an
optional \texttt{workCenterNoJson} (JSON array of work centre numbers). It iterates all \modulename{Machine Center} records,
and for each machine it filters \modulename{MES Operation Execution} records
whose \texttt{Start Time} falls within the requested window. For each matched
execution it sums the \texttt{Cycle Quantity} fields from linked
\modulename{MES Operation Progression} records to obtain \texttt{totalProduced},
and counts records marked as scrap to obtain \texttt{totalScrap}. Running
minutes are derived from the difference between \texttt{End Time} (or the
current datetime for open executions) and \texttt{Start Time}. Uptime
percentage is computed as \texttt{runningMinutes / (hoursBack × 60) × 100},
capped at 100.

\subsubsection{Activity Log Aggregation}

\texttt{fetchActivityLog()} queries four tables in descending timestamp order,
filtered to the \texttt{hoursBack} window: \modulename{MES Operation State}
(type \texttt{status\_change}), \modulename{MES Operation Progression} (type
\texttt{production}), \modulename{MES Operation Scrap} (type \texttt{scrap}),
and \modulename{MES Component Consumption} (type \texttt{scan}).
For each record the operator's first and last name are resolved from the
\modulename{Employee} table via the \texttt{Operator Id} foreign key. The
results are merged into a single chronological list before being returned as
a JSON array.

\subsection{Frontend Implementation}

\subsubsection{Shared HTTP Infrastructure}

All services in this sprint (and retroactively migrated services from earlier
sprints) use a shared \techname{HttpClient} and \techname{HttpResponseParser}
layer, replacing the inline \texttt{http.post} calls used in Sprint~1.

\textbf{\modulename{HttpClient.post()}}: centralised \texttt{http.post} wrapper
that injects JSON content-type headers and encodes the request body. All
services call this method rather than the raw \texttt{http} package directly.

\textbf{\modulename{HttpResponseParser}}: provides four static methods.
\texttt{parseList()} decodes \techname{Business Central} OData list responses
(nested value string). \texttt{parseObject()} decodes single-object responses.
\texttt{parseWriteResult()} decodes write-result responses and throws with the
backend error message on failure. \texttt{\_assertSuccess()} validates HTTP
status codes and throws a structured exception for non-2xx responses.

\subsubsection{User Interface}

Figures~\ref{fig:s4-ui-machine-dashboard} and~\ref{fig:s4-ui-activity-log} illustrate
the two  pages. The \uilabel{Machine Dashboard Page} renders
one card per machine, each displaying a circular uptime
indicator and four metric rows (operations, produced, scrap, running minutes);
the AppBar hosts a time-range dropdown that re-fetches data on change. The
\uilabel{Activity Log Page} presents a paginated list of all system events
ordered newest-first; each row shows a type icon, operator name, machine, action
text (expandable for long entries), and timestamp; type and time-range dropdowns
in the AppBar narrow the view.

\section*{Conclusion}
\addcontentsline{toc}{section}{Conclusion}

This sprint completed the \domainterm{MES} solution by delivering the
administration layer and cross-cutting quality-of-life features. Administrators
can now monitor the production health of the entire facility through a
configurable machine performance dashboard, audit all operator and machine
actions through a paginated activity log, and manage users from a persistent
navigation shell without losing context between sections. All users benefit from
full internationalisation covering English, French, and Arabic with automatic
right-to-left layout, and from guided coach-mark tutorials that ease onboarding
for first-time users.
